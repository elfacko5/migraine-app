Now

What is not working

  1. Attack mode is in the middle. The thing you reach for mid-attack sits below two big tile pickers you set once and forget.
  2. The explanation comes after the decision. What attack mode does is described under its switches.
  3. The page is three screens long, mostly because two binary choices (theme, font) use 170px tiles.
  4. Two dims are mixed up. The everyday "Overlay" slider has a preview labelled "How the dim looks during an attack". Attack mode really uses a fixed 35% floor you can not see or change.
  5. Developer words. "Overlay", "reflows rather than clipping", XS/SM/MD/LG/XL in 10px caps.
  6. The dim preview is an empty box. It does update live, and it has to: the real dim sits under the settings sheet. But an empty box is hard to judge. A line of text inside it would show the effect better.
  7. Repeated label. Section "Attack mode", switch "Attack mode", switch "Attack mode when I start an attack".

Notes

  • Same grammar as Medications (15d) and Edit a medicine (15f): grouped rows, label left, value right, chevron to drill in.
  • Attack mode moves to the top. It is the one thing someone looks for mid-attack, so it should never sit below the fold.
  • Its row uses the same mark as the attack mode button on Today, so the two read as one feature. No subtitle: the switch shows on or off by itself.
  • The second switch is renamed "When I log an attack". The old label repeated "Attack mode" and was two lines long.
  • Theme stays inline as a small segmented control. Each segment draws 36px but takes a 44px tap area, like .tap-44-y.
  • Font drills in even though it is also a choice of two. You need to see each font set in real text to choose, and that needs more room than a row.
  • The Text size value reads "iPhone" when it follows the iPhone setting (see A1b).
  • Surfaces follow medications.html: bg-base page with bg-surface groups. Today ProfileSubPage puts sub-pages on bg-surface with bg-raised groups, so the code needs to follow the v3 design when this is built.
  • Today the page is three screens long. This fits on one at default text size.
  • Open question: does the Attack mode switch earn its place here, given the button on Today? Keep it for now, since Settings is the only way in from other tabs.

Notes

  • The real dim (BrightnessOverlay, z-35) sits under every Sheet (z-50), so the page behind can never show it. The preview has to live inside the sheet, as the current swatch does.
  • The swatch is a real log card, not an empty box, so the dim is judged on text. It mirrors the overlay recipe, rgba(20,20,15,value), on every tap.
  • Range and steps match today: 0 to 80% in steps of 5, so saved values carry over. Holding − or + repeats, so 16 steps never means 16 taps.
  • Big − and + targets are easier than a thin slider when your head hurts or your hands are unsteady.
  • The value reads "20% darker than normal" instead of "Overlay 0%". "Overlay" is a developer word.
  • The old preview said "How the dim looks during an attack" under the everyday slider. That mixed the two settings. Attack mode dim now lives in A4.
  • If both are set, Lidd uses whichever is darker. Same rule as today.
  • "Turn off" sets 0% and closes. Sheet comes from the bottom with a grab bar, as it interrupts rather than drills in.
