17 · Screen shell: fixed header/footer, independent scroll

Most screens on this canvas use one scrolling frame top to bottom, with the footer CTA placed via margin-top:auto so it rides along with the content. On 21c, once the expand-in-place medication card grows the page, that CTA scrolls out of reach — not best practice for a primary action.

!Three fixed regions: header, scrolling middle, footerFor the code build — canvas not swept

This is the structural rule for every screen with a header and a footer CTA, whether or not this canvas's own files have been updated to show it — 21c is the one worked example, not a one-off.

<div class="screen" style="height:100%;display:flex;flex-direction:column;overflow:hidden"> <div class="screen-header" style="flex:none">...</div> <div class="screen-body" style="flex:1;overflow-y:auto">...</div> <div class="screen-footer" style="flex:none;border-top:1px solid var(--border)">...</div> </div>

Three rules: (1) the outer shell is overflow:hidden, never overflow-y:auto — it doesn't scroll itself. (2) header and footer are flex:none, fixed height, outside the scroll. (3) only the middle (screen-body) scrolls, and it alone carries flex:1;overflow-y:auto. The footer keeps a hairline top border (border-top:1px solid border token) so it reads as a bar sitting above content, not a button floating at the end of it.

Applies to any screen with a scrollable body and a persistent footer action — not just where content currently happens to overflow, since that can change per-user (more medicines, longer notes, a taller list).

18 · Chip layout: fill rows, no orphans

Chip groups wrap, and the order they are written in decides how ragged the result is. 21d “Also had” leaves short rows and single chips on a line.

✓Pack rows first, then orderRule, 20 Nov

(1) Fit as many chips per row as the width allows (screen content width 350 at 390, 8px gap). Pair long chips with short ones so each row is as full as possible.

(2) No row with a single chip, especially the last row. If one is left over, reorder or swap chips until it shares a row. A chip that fills a whole row on its own (for example a long label) is the only exception.

(3) Order is free for pick-any groups, so arrange for fit. Do not reorder anything with a natural order: scales, times, Yes / A bit / No. “+ Add your own” is a text link under the group, not a chip, so it never counts as an orphan.

(3b) When flex-wrap can't avoid an orphan (for example 4 chips that wrap 3 + 1), put each row in its own line of chips so they sit 2 + 2. Chips always hug their text; never stretch them into equal grid cells.

(4) Measure with the selected state: a selected chip gains a check and grows by about 28px, so a row that fits unselected can wrap when tapped. Either reserve the check space on every chip or leave that much slack in each row.

Applies to every chip group on the canvas and in code. Swept so far: 21d (all three groups, widths measured in Lexend 16). Still to check: the other chip groups on the canvas.
