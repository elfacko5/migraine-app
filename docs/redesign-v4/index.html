Known gaps — do not fill these in without a design pass

  • Light mode does not exist for any approved screen. Every mock in this export is dark-mode-only, by the designer's own working preference during this redesign. If the shipped app must honour the OS light/dark setting, this needs its own design pass before code treats dark as the only path.
  • Attack-mode "on" is drawn once (the Display & attack-mode settings screen, as a before/after of that one row). No screen shows what Today, Logs, or any flow screen looks like while attack mode is actually active (softened colours, dimmed illustration) beyond that one comparison.
  • No error states exist for: failed file import, network loss mid-sync, a sync conflict, or a corrupted/invalid backup file on Data (export/import/delete). The only "error-adjacent" states drawn anywhere are a duplicate medication name (15a-2) and the above-dose-limit warnings in the live/past/update flows, which are informational, not failure states.
  • 200%-text variants exist for only four screens (two medication-add steps, one edit-medication step, one Insights medication chart). Nothing else has been checked at the largest Dynamic Type size.
  • The 4-step end-of-attack variant (attack with no medication logged, so step 2 — "did it help?" — is skipped) is approved in principle but not drawn as its own screen; the counters on the drawn 5-step path still read "Step N of 5".
  • Inline "add a medication" exists only inside the past-attack flow (21c-6). The live flow and update flow do not have it yet.
  • Reminders screen is incomplete — it is missing the fixed/standing reminder row. The designer needs the current shipped app's reminder settings to finish it.
  • The morning prompt (24-0, "is the attack still going?") is still an open question with the designer — it may be cut in favour of auto-closing an attack or a "finish this entry" row in Logs. Do not treat it as final.
